# Supabase Usage Inventory - Marketing Container

## Executive Summary

Marketing container requires `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` for public-facing functionality.

**DOES NOT REQUIRE**: `SUPABASE_SERVICE_ROLE_KEY` - this is only used by Admin and Account pages which should not be in the Marketing container.

## Security Analysis

### Why SUPABASE_SERVICE_ROLE_KEY Should NOT Be in Marketing

1. **Service role bypasses Row Level Security (RLS)**
2. **Full database access with admin privileges**
3. **Never expose to browser/client-side code**
4. **Should only exist in server-side Admin/LMS routes**

### Current Issue

The following pages in `app/` (Marketing scope) use `requireAdminClient` which requires `SUPABASE_SERVICE_ROLE_KEY`:
- `app/account/plan/page.tsx`
- `app/account/addons/page.tsx`

**Recommendation**: These pages should be moved to the LMS container where the service role key belongs.

---

## Recommendation

### For Marketing Container (WWW)

Add ONLY the public variables:
```
NEXT_PUBLIC_SUPABASE_URL=<supabase_project_url>
NEXT_PUBLIC_SUPABASE_ANON_KEY=<supabase_anon_key>
```

### Do NOT Add
```
SUPABASE_SERVICE_ROLE_KEY
```

### For Account/Admin Pages

Move these routes to their respective containers:
- `/account/*` → LMS container
- `/admin/*` → Admin container
