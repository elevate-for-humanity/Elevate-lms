# E2E desktop-chrome triage (monorepo Playwright topology)

Command: `pnpm exec playwright test --project=desktop-chrome` (also available as `pnpm test:e2e`,
gated on PRs to `main` by `.github/workflows/e2e-desktop-chrome.yml`).

## Topology

`playwright.config.ts` now expands every device project (`desktop-chrome`, `laptop-chrome`,
`tablet-chrome`, `iphone-webkit`, `android-chrome`) once per app. Each variant keeps the device
project name, so `--project=desktop-chrome` still selects all three apps.

| App       | Workspace            | Local origin            | Override env               | Specs                                       |
| --------- | -------------------- | ----------------------- | -------------------------- | ------------------------------------------- |
| Marketing | `@elevate/marketing` | `http://localhost:3000` | `PLAYWRIGHT_MARKETING_URL` | `SPECS.marketing` in `playwright.config.ts` |
| Admin     | `@elevate/admin`     | `http://localhost:3001` | `PLAYWRIGHT_ADMIN_URL`     | `SPECS.admin`                               |
| LMS       | `@elevate/lms`       | `http://localhost:3002` | `PLAYWRIGHT_LMS_URL`       | `SPECS.lms`                                 |

- `webServer` is an array: one `pnpm --filter <workspace> dev --port <port>` per selected app.
  It is skipped for an app whose origin is overridden (deployed run).
- `PLAYWRIGHT_APPS=marketing,lms` limits the run (and the servers started) to a subset of apps.
- `PLAYWRIGHT_BASE_URL` (legacy) still works for deployed smoke runs. Cross-app links resolve to the
  production peer hosts (`tests/e2e/helpers/app-origins.ts` → `peerOrigin()`).
- `tests/e2e/global-setup.ts` reads each project's `metadata.app`/`baseURL`. It only warms the
  apps in the run, only warms Admin routes on the Admin origin, and skips an app that is
  unreachable or deployed. It also skips authenticated Admin warm-up when `TEST_ADMIN_*` is unset.

## Dead files

- `tests/e2e/enrollment-flow.test.ts` was **not** a Playwright test. It was a standalone Supabase
  script (`createClient` + `console.log`, no `test()` calls), so renaming it would have produced
  an empty or broken spec. It was converted to `tests/e2e/enrollment-lifecycle.spec.ts`, which
  keeps the same lifecycle (user → profile → enrollment → completion → certificate → cleanup). The
  spec is gated on `E2E_DB_LIFECYCLE=1` plus `NEXT_PUBLIC_SUPABASE_URL` and
  `SUPABASE_SERVICE_ROLE_KEY`, because it writes records.
- `tests/e2e/public-navigation-audit.ts` exports `registerPublicNavigationAudit()` and is imported by
  `public-runtime-acceptance.spec.ts`. It is a helper, so it moved to `tests/e2e/helpers/`.

## Baseline run (local, no Supabase / no test credentials)

Environment: all three dev servers started by Playwright and reachable. `TEST_ADMIN_*`,
`TEST_STUDENT_*`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` and
`SUPABASE_SERVICE_ROLE_KEY` were **unset**. Server logs recorded 219 `SUPABASE_CONFIGURATION_MISSING`
and 168 `SUPABASE_SERVICE_ROLE_KEY is not set` errors.

Result: **198 passed, 201 failed, 40 skipped (credential-gated `test.skip`), 41 did not run**
(serial describes after a failed step), 54.8 min.

The suite does **not** exit 0. Every failing spec is listed below with its category, root cause
and follow-up. No assertion was deleted or skipped.

## Required environment for a green gate

GitHub Actions secrets, read by `.github/workflows/e2e-desktop-chrome.yml`. Use a non-production
Supabase project.

- `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`
- `TEST_ADMIN_EMAIL`, `TEST_ADMIN_PASSWORD` (seeded admin)
- `TEST_STUDENT_EMAIL`, `TEST_STUDENT_PASSWORD` (seeded learner enrolled in a program)
- `TEST_PROGRAM_HOLDER_EMAIL`, `TEST_PROGRAM_HOLDER_PASSWORD`
- Seed data: published programs and pricing, published HVAC course media, and the QA learner.
- Optional: `E2E_DB_LIFECYCLE=1` enables `enrollment-lifecycle.spec.ts`. It writes, then deletes,
  disposable records.
