# Shared Program Holder dashboard simplification

The live authorized portal preview repeated setup instructions, readiness summaries, task lists, community prompts and student rosters on its landing screen. The shared landing page now provides one organization overview, one illustrated training guide, one next-task section, one bounded student snapshot, and office links. Detailed setup and role-specific terms remain available on demand. Students, Applicants, Programs, Hours, Documents, Compliance, Reports, Payouts, Settings and the regional launch guides retain their canonical routes and actions.

The Applicants page no longer repeats the same people in a call list and a second table. Protected contacts remain protected. Bulk applicant and alumni actions move to their corresponding roster pages. The previously inert student search/status controls now submit real server filters over the already-authorized roster.

Program Holder and Site Coordinator orientation now contain thirteen illustrated topics, including date checks, recipient selection, hours, weekly reporting, meetings, and career/community support. The Gary launch reference opens with the same visual training and keeps long regional contacts/templates in an expandable reference. Newer learner/apprentice/HVAC guide additions from main are preserved.

Recipient suggestions include canonical current/completed enrollments and legacy assigned applicants, page the full roster, remove duplicate addresses, and use linked account emails when an enrollment email is missing. Identity, active holder scope, existing agreement/contact-release rules and revoked-enrollment exclusion remain enforced. Suggestions grant no mailbox membership. The composer offers an explicit recipient selector; choosing an address adds it without sending a message.

Private data review: eleven assigned enrollment records were inspected. Three original voucher attachments were visually inspected; their service dates agree with the recorded voucher/schedule dates. Two additional voucher records have source references whose originals have not all been reopened. An authoritative agency message confirms one learner's actual completion date, which properly differs from the projected date. Missing dates and source-document access remain explicit gaps; no completion, credential, payment, voucher approval, signature or training date was fabricated or automatically changed. Personal records and document identifiers are intentionally excluded from this public source audit.

Baseline: prior main validation reported 762 test files, 4,870 passing tests and five skipped tests. This change passes 43 focused UI, filtering, directory, role, routing and payout regressions; four shared orientation contracts; changed-source ESLint; and the affected LMS TypeScript check. The full three-application recheck and production builds are still pending and are not claimed as passed. Production acceptance requires the corresponding Google revision, not merely a merged source commit.
